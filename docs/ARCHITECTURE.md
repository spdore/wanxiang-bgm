# Architecture

## Desktop host

The application is a C# 5 / .NET Framework 4.8 WinForms process. `Program` creates the audio engine, global hotkey service, and `MainMenuForm`. The WinForms shell owns device enumeration, system file pickers, settings persistence, import orchestration, and native window controls. `app/ui/index.html` is embedded as a WebView2 resource; `WebInterface` exposes the bridge actions and state snapshots. Import progress and per-file results use an in-document themed modal in that same WebView2 document, while source-file selection remains a native picker. Operation IDs isolate import progress and completion callbacks from later tasks. C# sources are grouped under `app/src/Audio`, `app/src/Features`, `app/src/Platform`, `app/src/Settings`, `app/src/UI`, and `app/src/Core`; the compiler recursively includes these modules.

## Audio and playback

`AudioEngine` owns the single BGM session and the microphone/cable/headphone streams. Session and generation identities guard asynchronous load, seek, completion, and stop callbacks. The engine captures only the selected physical microphone and this application's BGM, then renders their mix to CABLE Input. Chat software records CABLE Output. The two BGM gain controls remain independent; music gain is not applied to the microphone signal.

`Mp3Decoder.StreamingReader` uses Media Foundation for supported formats and is also the validation path for converted files. MP3 seeks decode forward from an accurate position rather than trusting an approximate VBR index. The anchor editor's audition is a distinct engine session that uses its unsaved draft range, is headphone-only, and does not update saved scene anchors. Playback completion notifications include session ID, seek generation, track ID, mode, and a natural/failed reason; explicit stops produce no completion event. These identities let continuous random playback advance only from the current valid session's completion on the WinForms UI thread.

Random playback mode is stored on each `ScenePreset`. Missing or invalid values normalize to normal one-track behavior. Continuous mode reuses the per-scene shuffle bag and its one-round no-repeat/boundary rule; candidate changes, scene changes, mode changes, explicit stops, previews, and shutdown invalidate the active run token. Failed or missing candidates are marked and skipped with a bounded attempt count, and a run ends when no usable candidates remain. Scene-pack export/import preserves the mode, with old packs defaulting to normal.

## Library and settings

`AppPaths` resolves user data at runtime. The installer does not bundle a music library or settings. `SongLibrary.Add` accepts only standard audio extensions, copies/reuses audio according to its existing filename rules, and adds membership to the active scene. Converted imports first reuse a same-extension library file when its full content matches. This keeps encrypted containers and `.wbgm` scene packs out of the playable/random candidate set.

Persistence-sensitive library operations use `SettingsStore.TrySave`. The importer snapshots the library and active scene before adding completed candidates. If the settings write fails, it restores those in-memory values and deletes only files newly copied by that import. Loudness measurement remains in the existing background analyzer and cache.

## Encrypted local import

The UI's existing **Add songs** action accepts standard audio and selected encrypted-container extensions. A single `SongImportOperation` runs at a time. The WebView2 document displays themed progress, cancellation, close, and per-file results; file inspection, conversion, and complete decode validation run on a worker thread. Escape requests cancellation during active work and closes the result only after completion. Closing the main window cancels the current operation. Completion callbacks carry the operation identity so an expired task cannot mutate a later import.

The importer assigns each batch an operation ID and sends file inspection, first-time helper extraction, encrypted conversion, Media Foundation probing/full decode, content deduplication, and large-file copying to disposable child processes. Helper extraction is attempted once per batch; a failed preparation does not repeat for every encrypted file. Children are started with fixed executable paths and `ProcessStartInfo`; Windows arguments are quoted directly and no shell is used. Each process is placed in an owned Job Object with kill-on-close so cancellation and timeout can stop descendants that inherited output pipes. Standard output/error are drained concurrently into bounded tail buffers. Converter status is parsed from bounded output; inspection, validation, and reuse results use small task-local result files. A result is accepted only after its process tree has stopped. An unresolved process tree marks cleanup unsafe and leaves its task directory intact.

File inspection has a 30-second deadline. Probe, full-decode, conversion, deduplication, and copy deadlines scale with the inspected input size and have fixed ceilings. Copy also has a 120-second no-progress deadline because it emits byte-count progress; stages without a progress protocol do not treat quiet output as a stall. The bundled archive extraction is limited to 60 seconds, 512 MiB expanded data, and 512 entries. Timeout policy is centralized in `ImportTimeoutPolicy` and described with exact defaults in [`ENCRYPTED_FORMAT_SUPPORT.md`](ENCRYPTED_FORMAT_SUPPORT.md).

After candidate files have been copied into same-directory temporary files, the UI commit only moves prepared files into final names and updates scene metadata. `SettingsStore.TrySave` remains the existing synchronous atomic XML settings write; bulk audio copy, hashing, conversion, and decoder work do not run in that callback. A settings-volume stall was not fault-injected in this change.

The helper uses the MIT-licensed decoder subset documented in [`../vendor/music-geshizhuanhuan/UPSTREAM.md`](../vendor/music-geshizhuanhuan/UPSTREAM.md). It identifies NCM and KGM/VPR from their file headers and QMC v1/v2 from recovered audio signatures or parsed trailers. QMC v2 variants with embedded QTag or PcV1Legacy EKeys use the upstream Map/RC4 implementation. MusicEx/STag without an embedded key returns `KeyUnavailable`; unknown structures are rejected. `.mflac` and `.mgg` select neither an algorithm nor an output extension. The actual decrypted header determines the output container.

Before import, the host verifies the output header and reads the complete output through the same streaming decoder used by playback. Decryption success and local-player decode success are reported separately. Unsupported Windows codecs do not create library entries. The host reuses a byte-identical same-extension library file when present, then passes the result to `SongLibrary.Add` and the established loudness analysis queue. Cleanup is restricted to the current GUID task directory; source files are never deleted or overwritten.

The vendored decoder still materializes encrypted input and decoded output in memory. The helper rejects encrypted inputs above 256 MiB and decoded output above 512 MiB before writing it into the task directory. This bounds payload sizes but does not make decoding streaming; peak memory can still reach several hundred MiB. Real platform-file compatibility remains sample-dependent; the support matrix records the variants and the lack of an authorized user `.mflac`/`.mgg` sample for this timeout fix.

## Build and distribution

`build.ps1` invokes the installed .NET Framework C# compiler directly with `/langversion:5`. It embeds the HTML interface, converter notice, and a ZIP containing the x64 onedir helper. The helper is built on Windows with pinned CPython/OpenSSL/PyInstaller/PyCryptodome versions; users do not install Python. The public installer embeds the player, third-party notice file, WebView2 SDK assemblies/loader, Microsoft's official WebView2 Bootstrapper, and the official signed VB-CABLE archive. It starts with an empty library and excludes user data.

The installer version in this source tree is 1.9.8. The README identifies downloadable GitHub releases separately from the current repository source. Build scripts refuse to overwrite an existing player or installer output. Installer removal deletes the installed program files and preserves the user's public-release music/settings and shared VB-CABLE/WebView2 dependencies. Development-profile data remains in its separate locations.
